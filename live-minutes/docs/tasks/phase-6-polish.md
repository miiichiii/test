# Phase 6: 仕上げ

## 目的

実際の会議で毎回使える状態にする。項目は互いに独立しているので、1項目ずつ依頼してもよい。

## 先に読むもの

- [AGENTS.md](../../AGENTS.md)
- [DESIGN.md](../DESIGN.md) §4.5（NotesEngine）、§5（画面）、§6（プライバシーと障害時の動作）

## 最初に確認すること

DESIGN.md §8 の #7（専門用語を音声認識に反映させるAPI）をSDKと公式ドキュメントで確認し、結果を表に書き込む。該当するAPIがない場合、項目3の音声認識への反映は行わず、その旨を報告する。

## 作業内容

1. エラーと状態の表示
   - 認証エラー、レート制限、ネットワーク断、モデルIDの誤りを区別し、次に何をすればよいかが分かる文言で表示する
   - ネットワーク断の間はノートペインに「オフライン。文字起こしは継続中」と表示し、復帰したら自動で再開する
2. 長い会議への対応
   - ノートが大きくなったら（目安: JSONで6,000文字超）、Luna への入力を「全トピックのタイトル」と「直近3トピックの全項目」に絞る
   - 絞った場合でも、省いたトピックへの `add_item` は適用できる
   - 2時間の会議を想定し、文字起こしの表示が重くならないようにする（表示の遅延読み込みなど）
3. 用語の登録
   - 設定画面で、固有名詞や専門用語を登録できる
   - 登録した用語を、Luna と Sol への入力の `glossary` に入れる
   - 確認したAPIがあれば、音声認識にも反映する
4. 録音中のスリープ防止
   - 録音中はMacがスリープしないようにし、停止時に解除する
5. メニューバー常駐とショートカット
   - メニューバーのアイコンから、開始 / 一時停止 / 停止ができる。録音中であることがアイコンで分かる
   - 開始 / 停止と「要約の送信を一時停止」のキーボードショートカット
6. ノートの手動編集
   - 項目の文言を直せる。項目を削除できる
   - 手で直した項目は固定し、以降の `update_item` と `remove_item` を無視する（参加者が直した内容をモデルが上書きしないようにするため）
   - 固定の規則を DESIGN.md §4.4 の適用規則に追記する
7. テスト
   - 入力の絞り込み（しきい値の前後、省いたトピックへの追加）
   - 固定した項目へのopが無視されること
   - エラーの種類ごとに、表示用の状態が正しく決まること

## 範囲外

- Mac内の音声の取り込み（Phase 7）

## 受け入れ条件

- ビルドとテストが通る
- スリープ防止が、停止・異常系のどちらでも解除される

## 人が確認する項目

- 誤ったAPIキーにすると、原因と対処が分かるメッセージが出る
- 登録した用語が、ノートと議事録で正しい表記になる
- 1時間ほど使っても、画面の動きが重くならない
- 録音中にMacがスリープしない。停止後は通常どおりスリープする
- メニューバーとショートカットから操作できる
- 手で直した項目が、その後の更新で書き換えられない
