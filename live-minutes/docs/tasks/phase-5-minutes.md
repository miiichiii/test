# Phase 5: 議事録と履歴

## 目的

会議の終了時に議事録を作り、過去の会議を後から開けるようにする。このフェーズで当初の目的は一通り満たせる。

## 先に読むもの

- [AGENTS.md](../../AGENTS.md)
- [DESIGN.md](../DESIGN.md) §4.6（MinutesWriter）、§4.9（Persistence）
- 議事録仕上げ用のシステムプロンプト（Phase 3 でパッケージのリソースに移したもの）

## 作業内容

1. `Notes/`: `MinutesWriter`
   - 入力JSONの組み立て（`meeting`、`transcript`、`notes`）
   - 議事録仕上げ用のモデルに、テキストのストリーミングで依頼する
   - 完了したら `minutes.md` に保存する。途中で失敗した場合、不完全な内容を保存しない
2. `SessionController` との接続
   - `finishing` の中で、最終確定 → 残りのライブ更新 → 議事録の生成 の順に行う
   - 議事録の生成に失敗してもセッションは `finished` にし、後から作り直せるようにする
3. `SessionRepository` の拡張
   - セッションの一覧（新しい順）、読み込み、削除
   - `notes.json` と `minutes.md` の読み書き
4. 画面
   - 終了後の表示: 議事録 / ノート / 文字起こし を切り替えて見られる
   - 議事録は、届いた分から順に表示する
   - 議事録のコピー、Markdownでの保存、「作り直す」ボタン
   - サイドバーに過去のセッションの一覧。選ぶと内容が開く。削除は確認してから行う
5. テスト（偽の `LLMClient` を使う）
   - 入力JSONに文字起こし全文とノートが入っている
   - ストリーミングの差分が順に連結される
   - 途中で失敗した場合に `minutes.md` が作られない、または以前の内容が残る
   - `SessionRepository` の一覧、読み込み、削除
   - 壊れたセッションフォルダ（`meta.json` がないなど）があっても、一覧の取得が失敗しない

## 範囲外

- エラー表示の作り込み、メニューバー常駐（Phase 6）

## 受け入れ条件

- ビルドとテストが通る
- 録音中に、過去のセッションを開いても録音が止まらない（または、録音中は切り替えられないようにしてある）

## 人が確認する項目

- 会議を停止すると議事録が流れるように表示され、決定事項とToDoが漏れていない
- 議事録に、話していない内容が書かれていない
- アプリを再起動しても、過去の会議の議事録・ノート・文字起こしを開ける
- 「作り直す」で議事録が生成し直される
- セッションを削除すると、保存フォルダからも消える
