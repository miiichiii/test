# Phase 4D: Whisper（ローカル）での書き起こし

## 目的

Apple の音声認識に加えて、Whisper のモデルを Mac の中で動かす書き起こしを、設定画面で選べるようにする。両方を実際の会議で試し、精度と遅れを比べられるようにする。音声は外に出さない。

Phase 4C の後に、利用者の求めで追加したフェーズ。番号は順序を表すだけ。

## 先に読むもの

- [AGENTS.md](../../AGENTS.md)（外部ライブラリの例外を含む）
- [DESIGN.md](../DESIGN.md) §4.2（Transcription。特に「Whisper（ローカル）での書き起こし」）、§4.8（Settings）、§5（画面）

## 最初に確認すること

- Argmax OSS（`https://github.com/argmaxinc/argmax-oss-swift.git`）の最新のリリースの版を調べ、`Package.swift` に `exact:` で固定する。LICENSE と NOTICES を読み、ライセンスを報告する
- 取得したパッケージのソースで、使う API（初期化の設定、モデルのダウンロードと保存先の指定、Float の配列の書き起こし、言語の指定、進み具合の受け取り）の名前と形を確かめる。README の例や記憶に頼らない
- モデルの名前と大きさを、Hugging Face の `argmaxinc/whisperkit-coreml` で確かめる
- Swift 6 の厳格な並行性チェックで、パッケージの型をそのまま使えるか確かめる。使えない場合は、actor か `@unchecked Sendable` の包みに閉じ込め、理由をコメントに書く
- DESIGN.md §8 の #14 を表に書き込む（確かめられないものは「未確認」）

## 作業内容

1. `Package.swift` に Argmax OSS の `WhisperKit` を足す（版を固定）
2. `Transcription/`
   - `WhisperTranscriber`（protocol）と、WhisperKit を使う実装
   - 音声の区切り（無音と長さの上限）の純粋なロジック
   - `WhisperLocalEngine`（`TranscriptionEngine` の実装）: 区切りごとの確定、約2秒ごとの途中結果、停止時の最後の区切り
   - `TranscriptionError` に、モデルがない・読み込みの失敗などを足す
3. モデルの管理: ダウンロード（進み具合・キャンセル）、保存先、削除、あるかどうか
4. `Settings/`: 書き起こしの方式とモデルを `AppSettings` に足す
5. 起動処理: 設定に従って、会議の開始時に使うエンジンを選ぶ（次に開始する会議から反映）
6. 画面
   - 設定画面の「文字起こし」の節に「書き起こしの方式」（Apple / Whisper（ローカル））、モデルの選択、ダウンロード・削除のボタンと進み具合
   - モデルがないまま Whisper で開始しようとしたときの案内
7. テスト（モデルはダウンロードしない）
   - 区切り: 無音での区切り、長さの上限、短すぎる区切りの扱い、時刻の計算
   - エンジン: 偽の `WhisperTranscriber` で、確定・途中結果・停止時の最後の区切り・失敗
   - 設定の保存と読み込み

## 範囲外

- Whisper を OpenAI の API で使うこと（音声を外に出すため）
- 話者の区別
- Mac 内の音声の取り込み（Phase 7）

## 受け入れ条件

- ビルドとテストが通る
- 書き起こしの方式が「Apple」のとき、動作が今までと変わらない
- 自動テストがモデルをダウンロードしていない

## 人が確認する項目

- 設定画面でモデルをダウンロードでき、進み具合が出る。キャンセルと削除ができる
- 「Whisper（ローカル）」で会議をすると、話した内容が文字になる。途中結果も出る
- 同じような内容を Apple と Whisper の両方で話し、精度（固有名詞・専門用語を含む）と遅れを比べる。気になった例をメモする
- 初回の準備（モデルの読み込み）にかかる時間と、会議中のメモリと CPU の使い方（アクティビティモニタ）
- Wi-Fi を切っても、Whisper で書き起こせる
- モデルがないまま Whisper で開始しようとすると、案内が出て開始しない
- 一時停止・再開・停止で、最後まで文字になる
- 「Apple」に戻すと、今までどおり動く
