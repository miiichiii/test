# Phase 4: ライブ整理

## 目的

会議中に、確定した文字起こしが自動で整理され、右ペインに箇条書きとして増えていくようにする。このアプリの中心となる機能。

## 先に読むもの

- [AGENTS.md](../../AGENTS.md)
- [DESIGN.md](../DESIGN.md) §4.5（NotesEngine）、§5（画面）、§6（プライバシーと障害時の動作）
- ライブ更新用のシステムプロンプト（Phase 3 でパッケージのリソースに移したもの）

## 作業内容

1. `Notes/`: `NotesEngine`（actor）
   - 確定セグメントを受け取ってためる
   - 送信の条件は DESIGN.md §4.5 のとおり（120文字 / 20秒 / 最短8秒 / 同時1本 / 停止時は残りを送る）。値は `AppSettings` から読む
   - 入力JSONの組み立て（`meeting`、`notes`、`recent_context`、`new_transcript`）
   - 応答のopsを `NotesReducer` で適用し、`NotesStore` と `notes.json` に反映する
   - 失敗時は、送ろうとしたセグメントを未送信のまま保持する
   - 「要約の送信を一時停止」中のセグメントは捨てる（後から送らない）
   - 時計と `LLMClient` を外から渡せるようにする
2. `SessionController` との接続
   - 確定セグメントを `NotesEngine` に渡す
   - 停止時に、残りの送信が終わるのを待つ（上限時間を設け、超えたら打ち切って先へ進む）
   - APIキーが未設定の場合は `NotesEngine` を動かさず、文字起こしだけを続ける
3. 画面
   - 右ペイン: トピックごとに項目を表示する。種類はラベルの文字つきのバッジで示す。ToDoには担当と期限を添える
   - 追加・更新された項目を数秒間ハイライトする
   - ツールバー: LLMの状態（更新中 / 待機 / エラー）と「要約の送信を一時停止」トグル
   - APIキー未設定時は、右ペインに案内と設定画面へのボタンを表示する
   - ノートのMarkdownコピー
4. テスト（偽の `LLMClient` と偽の時計を使う）
   - 120文字に達したら送る / 達していなくても20秒で送る / 8秒以内は送らない
   - 応答待ちの間に届いたセグメントが、次の1回にまとめられる（同時に2本飛ばない）
   - 失敗した場合、同じセグメントが次回に再送される
   - 停止時に残りが送られる
   - 一時停止トグルがオンの間は送られず、その間のセグメントはオフにした後も送られない
   - 入力JSONが DESIGN.md §4.5 の例と同じ構造になっている
   - システムプロンプトがリクエストごとに同一の文字列である

## 範囲外

- 議事録の生成と履歴（Phase 5）
- ノートが大きくなったときの入力の絞り込み、項目の手動編集（Phase 6）

## 受け入れ条件

- ビルドとテストが通る
- LLMの失敗が、録音と文字起こしを止めない
- 文字起こしやノートの本文がログに出ていない

## 人が確認する項目

- 5分ほど会議のように話すと、右ペインに箇条書きが増えていく
- 「〜に決めましょう」「〜さん、金曜までにお願いします」のような発言が、決定事項やToDoとして、担当・期限つきで入る
- すでに表示されている項目が、更新のたびに並び替わったり書き換わったりしない
- 相づちや雑談が項目にならない
- 「要約の送信を一時停止」をオンにして話した内容が、オフに戻した後もノートに現れない（左ペインの文字起こしには残る）
- 会議中にWi-Fiを切っても文字起こしが続き、戻すとノートの更新が再開する
- 整理の質に不満がある場合は、気になった例をメモしておく（プロンプトの調整に使う）
