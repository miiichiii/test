# Phase 1: マイクと文字起こし

## 目的

マイクに向かって話した内容が、リアルタイムで左ペインに表示されるようにする。このアプリの土台であり、遅延と安定性をここで確かめる。

## 先に読むもの

- [AGENTS.md](../../AGENTS.md)（特に「新しいAPIの扱い」）
- [DESIGN.md](../DESIGN.md) §2（全体の流れ）、§4.1（Audio）、§4.2（Transcription）

## 最初に確認すること

DESIGN.md §8 の #1 と #2 を確認し、結果を表に書き込む。

- `SpeechTranscriber.supportedLocales` を出力する小さなコードを動かし、`ja-JP` が含まれるか確認する。エージェントの環境から実行できない場合は、確認用のコードをアプリに入れ（起動時にログへ出す）、人による確認項目として報告する
- `SpeechAnalyzer` / `SpeechTranscriber` / `AssetInventory` / `AnalyzerInput` の定義をSDKで確認し、DESIGN.md §4.2 の手順と食い違いがあれば設計書を直す

## 作業内容

1. `Audio/`: `AudioSource` と `MicrophoneSource`
   - マイク権限の確認と要求
   - tapで受けたバッファを非同期ストリームに流す
   - 入力レベルを取得できるようにする
   - 入力デバイスの変更（`AVAudioEngineConfigurationChange`）に対応し、録音を続ける
2. `Transcription/`: `TranscriptionEngine`、`AppleSpeechEngine`、`TranscriptEvent`、`TranscriptSegment`
   - DESIGN.md §4.2 の手順1〜8
   - ロケールが非対応の場合と、モデルのダウンロードに失敗した場合は、区別できるエラーにする
3. 画面
   - 「開始」「停止」ボタン
   - 左ペインに確定テキスト（通常の色）と未確定テキスト（薄い色）を表示する
   - モデルのダウンロード中は進捗を表示する
   - 権限がない場合は、理由と「システム設定を開く」ボタンを表示する
4. テスト
   - 音声形式の変換など、マイクなしで検証できる部分にテストを書く
   - 偽の `AudioSource`（用意したバッファを流す実装）を作り、以降のフェーズのテストでも使えるようにする

この段階では、確定セグメントの保持は画面用の単純な配列でよい（`TranscriptStore` と保存は Phase 2）。

## 範囲外

- 一時停止、保存、書き出し（Phase 2）
- LLM に関するコード

## 受け入れ条件

- ビルドとテストが通る
- 厳格な並行性チェックで警告が出ない
- tapのコールバック内で、ロックの取得や重い処理をしていない

## 人が確認する項目

- 初回起動でマイクの許可を求められ、許可すると録音が始まる
- 日本語で話すと、1〜2秒以内に薄い色のテキストが出て、数秒以内に通常の色で確定する
- 「停止」を押すと、話し終えた最後の部分まで確定される
- 5分間話し続けても、止まったり遅延が増え続けたりしない。アクティビティモニタでメモリが増え続けていない
- 録音中にイヤホンやマイクをつなぎ替えても、録音が続く
- マイクの許可を拒否した場合に、案内が表示される
